# TASK-152 — เชื่อม API สร้างสินค้า

สถานะ: CREATE_IMPLEMENTED_VIA_TASK177 / WAITING_FOR_UAT — 6 ตุลาคม 2569

## ข้อสรุปล่าสุด

เจ้าของยืนยันรวมรูปสินค้า/เอกสาร ไม่เกิน10MBต่อไฟล์. งานสร้างครบข้อมูล/private filesดำเนินการและผ่านการตรวจใน [TASK177](TASK-177-product-create-full.md) แล้ว แทนpreviewสร้างและขอบเขตไฟล์ที่เคยรอด้านล่าง. ใช้ดาวบังคับข้อมูลทั่วไปตามที่ตกลง ช่องยาที่กฎ conditional ยังOPENคงoptional. งานแก้รายละเอียดครบข้อมูลยังlocalตามTASK165. ข้อความสำรวจต่อจากนี้เป็นประวัติ ณ5ตุลาคม ไม่ใช่สถานะปัจจุบัน.

## คำขอและผลสำรวจ

เจ้าของต้องการ API เพื่อทดลองตั้งค่าข้อมูลพื้นฐานสินค้าและสร้างสินค้า. GET/POST/PATCH /api/product-options พร้อมเชื่อม DB และฟอร์มเลือก UUID แล้วจาก TASK151.

POST /api/products เดิมรองรับชื่อเดียว รหัส4หลักตามหมวด+รูปแบบยา และบังคับตัวยา/คลังเริ่มต้น/สถานะ. ฟอร์มใหม่มีชื่อไทยและอังกฤษ กลุ่มรหัส/รูปแบบรหัสแยกจากหมวด/รูปแบบยา เลข5หลัก ประเภทผลิตภัณฑ์ ยี่ห้อ ผู้ผลิต ข้อมูลยา/ทะเบียน ราคา/ภาษี และรูป/เอกสาร. ปุ่มบันทึกยังเป็น preview; ห้ามอ้างว่าสร้างสินค้าใหม่ได้แล้ว.

ขอบเขตรอคำตอบ: บันทึกข้อมูลทุกช่องโดยยังไม่แนบไฟล์ หรือรวมรูปและเอกสาร. ถ้ารวมไฟล์ ต้องสรุปขนาด/ชนิด/จำนวน/สิทธิ์และวงจรจัดเก็บตาม OPEN ก่อนลงมือ. ต้องไม่ทิ้งข้อมูลที่ผู้ใช้กรอกอย่างเงียบ ๆ.

กฎรอคำตอบเพิ่มเติม: เมื่อเลือกประเภทเป็นยา ต้องบังคับตัวยา/รูปแบบยา/ทะเบียนอย่างไร ตาม TASK124 ที่ยังไม่อนุมัติ conditional validation. ส่งคำถามสองเรื่องให้เจ้าของแล้ว ยังไม่ถือว่าคำตอบที่แนะนำหรือเวลาที่ผ่านไปเป็นคำอนุมัติ.

ผลตรวจรอบนี้: รัน scripts/test-product-options.mjs ผ่าน10หัวข้อกับ DB จริง ทั้ง seedครบ10ชุด/create/rename/audit/duplicate/version/disable/reopen/legacy UUID/validation/paging/role/origin/RLS. Fixtures rollback ทั้งหมด และยอด950หน่วยคงเดิม. git diff --check ผ่าน. ไม่มี schema หรือโค้ดสินค้าเปลี่ยนใน TASK152 รอบสำรวจ.

## แผนย่อย

1. ตรวจ ACTIVE/Specs/Plan และฟอร์ม/API/schema; รอบนี้แก้เอกสารสี่ไฟล์นี้และตรวจ API รายการกลางที่พร้อมแล้ว.
2. เมื่อขอบเขตพร้อม บันทึกสัญญาการบันทึกทุกช่องและการรองรับสินค้าเดิมใน Specs/Plan ก่อนโค้ด; ประเด็น OPEN ต้องมีคำตอบ ไม่เดากฎธุรกิจ.
3. Migration additive/schema และเส้น API เลขลำดับ/สร้างสินค้า: รหัส5หลักแยกตามคู่กลุ่มรหัส+รูปแบบตาม TASK126 เลือกรายการกลางที่เปิด ตรวจซ้ำ/concurrency/role/origin และ audit ใน transaction. รักษาสินค้าเดิมและไม่สร้างยอดสต็อกเพียงเพราะเพิ่มสินค้า.
4. เชื่อม product-create-preview.tsx และ picker กับ API; ตรวจครบช่อง แสดงข้อผิดพลาดจริง กันบันทึกซ้ำ แสดงผลจาก DB; งานไฟล์ขึ้นกับขอบเขตที่สรุป.
5. Integration rollback ตรวจการสร้าง/readback/validation/รายการปิด/เลขซ้ำ/สิทธิ์ และยอดตัวอย่าง950ไม่เปลี่ยน; lint/typecheck และ UAT.
