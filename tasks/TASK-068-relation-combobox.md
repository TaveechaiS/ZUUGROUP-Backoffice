# TASK-068 — ช่องค้นหาและเลือกข้อมูลช่องเดียว

สถานะ: READY_FOR_USER_TEST — เจ้าของขอและอนุมัติปรับ Combobox 2026-10-02

## Specs

ช่องข้อมูลสัมพันธ์ในฟอร์มเพิ่ม/แก้ไข เช่น ลูกค้า สินค้า ผู้ขาย ให้พิมพ์ค้นหาและเลือกรายการในช่องเดียว พื้นขาว ส่ง ID ที่เลือกจริงเท่านั้น ไม่สร้างข้อมูลใหม่จากข้อความที่พิมพ์ คง API options และ pagination 10 รายการเดิม

## แผนย่อย

1. บันทึกขอบเขตและตรวจ RelationPicker/API เดิม
2. แทนช่องค้นหา + select ด้วย input combobox และรายการ dropdown รองรับเมาส์ ArrowUp/Down Enter Escape Tab มีสถานะโหลด/ว่าง/ผิดพลาดและก่อนหน้า/ถัดไป
3. คงค่าที่เลือกเมื่อปิด dropdown และไม่บันทึกคำค้นเป็น ID; ตรวจ type-check/lint/diff แล้วเจ้าของทดสอบจริง

ไฟล์: src/components/pages/record-form-page.tsx และเอกสาร Specs/Plan/ACTIVE งานนี้ไม่เปลี่ยน select ของ role/status/filter หรือ DB

ผลที่ต้องได้: กดช่องเดียว พิมพ์แล้วเลือกลูกค้าได้ บันทึก ID เดิมโดยพฤติกรรมฟอร์มไม่เปลี่ยน

ผล: เปลี่ยน RelationPicker เป็น input/dropdown ช่องเดียวแล้ว รองรับ ArrowUp/Down Enter Escape Tab เมาส์และ pagination 10 ผ่าน API เดิม แสดงโหลด/ว่าง/error เก็บ ID เดิมเมื่อพิมพ์หรือยกเลิก และป้องกันผลค้นหาเก่าทับใหม่ Type-check/lint/diff ผ่าน ไม่ยิง API จริงอัตโนมัติ

ข้อจำกัดเดิมที่คงไว้: หน้าแก้ไขที่ ID ไม่อยู่ใน options หน้าปัจจุบัน แสดง “รายการที่เลือกไว้” จนเลือกรายการใหม่

## ⚠️ ต้องทดสอบโดยคุณ

1. เปิดเพิ่มรายการที่มีลูกค้า กดช่องลูกค้าแล้วพิมพ์ชื่อ/รหัส รายการใน dropdown ต้องกรองได้ในช่องเดียว
2. เลือกด้วยเมาส์ หรือ ArrowDown/Enter ช่องต้องแสดงรหัสและชื่อ บันทึกแล้วตรวจรายละเอียดว่าลูกค้าตรงกัน
3. ลองค้นหาคำที่ไม่มีรายการ ต้องแสดงไม่พบรายการ กด Escape/คลิกนอก/Tab แล้วค่าที่เลือกเดิมยังอยู่
4. ลองก่อนหน้า/ถัดไป และหน้าแก้ไขเดิม ตัวเลือกเปลี่ยนหน้าได้ ค่าที่เลือกไม่หาย และช่องสัมพันธ์อื่นใช้รูปแบบเดียวกัน
