# คู่มือเขต ลูกค้า รับเข้า และคำสั่งซื้อ

TASK-092 · 3 ตุลาคม 2569 · เวลาทั้งระบบ Asia/Bangkok

## เริ่มใช้งานตามลำดับ

1. Admin ไป **ลูกค้า → เขตและทีมขาย**. มีเหนือ/ออก/ตก/ใต้ให้เริ่มต้น เลือก Manager และ Sales จากบัญชีจริง. เว้นคนไว้ก่อนได้; คนเดียวอยู่สองเขตไม่ได้.
2. สร้างลูกค้า เลือก **กลุ่มลูกค้า** และ **เขตขาย**. เปลี่ยนเขตได้ภายหลัง; รายละเอียดแสดงชื่อเขตและทีมขาย. หน้ากลุ่มแยกเดิมจะพากลับหน้าลูกค้า. ข้อมูลเดิมยังเก็บอยู่.
3. สร้างข้อมูลสินค้าและกำหนดราคาขายตามเดิม. ข้อมูลหลักสินค้าเพียงอย่างเดียวยังไม่ใช่ยอดคงคลัง.
4. ไป **จัดซื้อ → รับสินค้าเข้าและล็อต** หรือ **สินค้า → ล็อตและยอดคลัง** แล้วกดรับสินค้าเข้า. กรอกแหล่งที่มา เลขล็อต จำนวน ต้นทุน วันผลิต วันหมดอายุ และคลัง. เพิ่มหลายล็อตในใบรับเดียวได้; ทุกล็อตได้ ID ใหม่เสมอ.
5. ช่องต้นทุนรับเข้าเป็น **ต้นทุนรวมล็อต** เช่น 1,000 ชิ้น ชิ้นละ 5 บาท = 5,000 บาท. ระบบคำนวณต่อหน่วยให้. Admin/CFO เห็นต้นทุน; ราคาขายยังเป็นราคาที่ Admin ตั้งในข้อมูลสินค้า.
6. Sales ไป **คำสั่งซื้อ → สร้าง Order** เลือกลูกค้า สินค้า จำนวน. ระบบเลือกล็อตที่หมดอายุก่อนตาม FEFO และจองจากคลังหลักทันที. ของพร้อมขายไม่พอสร้างไม่ได้.
7. Manager เปิด Order ตรวจหรือแก้รายการ แล้วกดอนุมัติ. การแก้รายการต้องผ่านอนุมัติใหม่. Manager/Admin ส่งกลับให้ Sales แก้ได้.
8. Admin เปิด Order ที่อนุมัติแล้ว ตรวจและจัดของจริง แล้วกด **ยืนยันจัดของและตัดคลัง**. สถานะเป็นเสร็จสิ้นและตัดของครั้งเดียว.

## อ่านยอดคลัง

- **คงเหลือ**: ของที่ยังอยู่ในคลัง
- **จอง**: ของที่กันไว้ให้ Order ที่ยังไม่เสร็จสิ้น
- **พร้อมใช้**: คงเหลือลบจอง; สำหรับขายต้องผ่านเกณฑ์อายุและสภาพสินค้าด้วย
- ส่งกลับแก้ไขยังเก็บจองไว้; แก้จำนวนคำนวณจองใหม่; ยกเลิกก่อนเสร็จสิ้นคืนจอง
- เอกสาร Order เก่าที่ไม่มีรายละเอียดสินค้าอ่านได้ แต่ไม่สร้างการจองหรือตัดของสมมติ

## อายุสินค้าและการย้ายคลัง

| งาน | เกณฑ์เริ่มต้น | สิ่งที่ผู้ทำต้องทำ |
|---|---|---|
| ขายจากคลังหลัก | เหลืออย่างน้อย 6 เดือนปฏิทิน | ระบบตรวจเมื่อจองและตรวจอีกครั้งตอน Admin ตัดของ |
| บริจาคจากคลังการตลาด | เหลืออย่างน้อย 12 เดือน ณ วันคาดว่าผู้รับได้รับ | ระบุผู้รับ วันรับ และยืนยันตรวจเงื่อนไขผู้รับ |
| แจกทั่วไปจากคลังการตลาด | ยังไม่หมดอายุและไม่เสื่อมสภาพ | ตรวจสภาพและความเหมาะสมก่อนแจกจริง |
| หมดอายุ/เสื่อมสภาพ | งดขายและงดแจก | Admin ย้ายของจริงไปคลังรอทำลายแล้วบันทึกโอน |

Admin ปรับเกณฑ์ได้ในหน้าล็อตและยอดคลัง. เกณฑ์ขาย6เดือนเป็นนโยบายบริษัทที่เลือกเริ่มต้น; การบริจาคต้องตรวจเงื่อนไขผู้รับด้วยตาม [WHO](https://www.who.int/publications/i/item/9789241501989). ระบบไม่ย้ายยอดอัตโนมัติและยังไม่มีขั้นตอนทำลายจริง. ถ้าฉลากเป็นเดือน/ปี ให้กรอกวันสุดท้ายของเดือนนั้น; ระบบงดขายตั้งแต่วันที่หมดอายุที่กรอก.

## หากกรอกผิดหรือยอดไม่ตรง

- **ยกเลิกข้อมูลผิดและบันทึกแก้ไข**: ภายใน7วันจากเวลารับเข้าครั้งแรก กรอกค่าที่ถูกและเหตุผล. ระบบเก็บก่อน/หลังและปรับเฉพาะผลต่าง ไม่สร้างของซ้ำ ไม่เปลี่ยน ID ล็อต ไม่ยกเลิก Order ที่ขายไปแล้ว.
- จำนวนใหม่ต่ำกว่าที่จ่าย/จองไปแล้วจะถูกปฏิเสธเพื่อไม่ให้เกิดยอดติดลบ. ตรวจเอกสารและของจริงก่อน.
- **ปรับยอดตามของจริง**: กรอกยอดที่นับได้และเหตุผล เป็นรายการแยก. การตรวจนับเดิมยังไม่ปรับยอดให้อัตโนมัติ.
- **โอนคลัง**: เลือกปลายทาง จำนวน และเหตุผล; โอนของที่จองไว้ไม่ได้. ประวัติโอนออกและโอนเข้าอ้างรายการเดียวกันและ Lot ID เดิม.
- ต้นทุนใน Order เสร็จสิ้นเป็นค่าขณะจ่าย; การแก้ต้นทุนล็อตภายหลังไม่เปลี่ยนต้นทุนขายเก่า. ตัวเลขส่วนต่างเป็นกำไรขั้นต้น ไม่รวมภาษี/ค่าใช้จ่ายอื่น.

## ชื่อ API ไทย / English

| API | ไทย | English | หน้าที่ |
|---|---|---|---|
| `/api/customers` | ลูกค้า | Customers | ข้อมูลลูกค้า กลุ่ม `category` และเขต `territoryId`; กรองตามเขตได้ |
| `/api/sales-territories` | เขตและทีมขาย | Sales territories | เขต `managerId`/`salesId`, CRUD และตัวเลือกชื่อ |
| `/api/users?view=options&roleId=MANAGER` | ตัวเลือกผู้จัดการ | Manager options | Admin เลือกบัญชีตามบทบาท; Sales ใช้ `roleId=SALES` |
| `/api/inventory?view=stock` | ล็อตและยอดคลัง | Lot stock | คงเหลือ จอง พร้อมใช้ และสถานะอายุสินค้า |
| `/api/inventory?view=receipts` | ประวัติรับเข้า | Goods receipts | ใบรับเข้า ล็อต และประวัติแก้ไข |
| `/api/inventory?view=movements` | ประวัติเคลื่อนไหว | Stock movements | จำนวนเข้า/ออก ต้นทาง เหตุผล ผู้ทำและเวลา |
| `/api/inventory?view=options` | ข้อมูลเลือกทำรายการ | Operation options | สินค้า ลูกค้า คลัง ผู้ใช้ปัจจุบัน และเกณฑ์อายุ |
| `POST /api/inventory` | ทำรายการคลัง | Inventory commands | `receive`, `correct`, `transfer`, `adjust`, `give`, `condition`, `policy` |
| `GET /api/orders` | คำสั่งซื้อ | Sales orders | รายการค้นหา/แบ่งหน้า; `/{id}` อ่านรายละเอียดและล็อตที่จอง |
| `POST /api/orders` | สร้างและจอง | Create and reserve | `code`, `customerId`, `lines[{productId,quantity}]`, `notes?`, `idempotencyKey` |
| `PATCH /api/orders/{id}` | ขั้นตอนตรวจและจ่าย | Order workflow | `edit`, `approve`, `return`, `complete`, `cancel` พร้อมรหัสคำสั่งและเวลารายการเดิม |
| `DELETE /api/orders/{id}` | ยกเลิกและคืนจอง | Cancel and release | ใช้เหตุผลและ `idempotencyKey` ก่อนเสร็จสิ้น |

List ใช้ `offset`, `limit` (สูงสุด50), `search`. คำสั่งต้องมี UUID `idempotencyKey`: retry คำสั่งและข้อมูลเดิมใช้ค่าเดิม เพื่อป้องกันบันทึกซ้ำ; เปลี่ยนข้อมูลเป็นคำสั่งใหม่ใช้ค่าใหม่. ทุก API ต้องเข้าสู่ระบบ; คำสั่งตรวจบทบาทและ Origin. ไม่เปิด API ต้นทุนให้ Sales/Manager.

## ⚠️ ต้องทดสอบโดยคุณ

ใช้ข้อมูลทดสอบของคุณแยกจากงานจริง แล้วตรวจบนคอมและมือถือ:

1. เลือก Manager/Sales ให้เขต → ชื่อขึ้นในรายละเอียดลูกค้า; คนซ้ำเขต/ผิดบทบาทต้องถูกปฏิเสธ
2. สร้างลูกค้า เลือกและเปลี่ยนเขต กรองกลุ่ม/เขต → ได้รายการตรงตามที่เลือก
3. รับสินค้าเดียว2ล็อต ล็อตละ10 → คงเหลือรวม20, ได้2 Lot ID, ต้นทุน Sales/Manager ไม่เห็น
4. Sales สร้าง Order10 → จอง10คงเหลือ20; ล็อตใกล้หมดอายุถูกเลือกก่อน
5. อีกคนสร้าง Order11 → ต้องไม่สำเร็จ เพราะพร้อมขายเหลือ10
6. Manager อนุมัติ → คงเหลือยัง20; Admin ยืนยัน → คงเหลือ10 จอง0 และสถานะเสร็จสิ้น
7. ส่งกลับ แก้จำนวน ยกเลิก และลองกดยืนยันซ้ำ → จอง/ยอดเปลี่ยนถูกครั้งเดียว
8. โอน/ปรับ/แก้รับ → มีเหตุผล ผู้ทำ เวลา และต้นทาง; แก้รับเกิน7วันต้องถูกปฏิเสธ
9. ล็อตหมดอายุ/เสื่อมสภาพขายหรือแจกไม่ได้; บริจาคไม่ผ่านเกณฑ์ต้องถูกปฏิเสธ
10. ค้นหา แบ่งหน้า ดูรายละเอียดจากแถว Loading ในข้อมูล และปุ่มยกเลิก/ยืนยัน → ใช้ได้ทั้งคอม/มือถือ

ยังรอรายละเอียด: ภาษี/ส่วนลด/เครดิต ใบแจ้งหนี้จริง ทำลายจริง คืนขายหลังเสร็จสิ้น ผู้จำหน่ายละเอียด และ Dashboard API. ไม่ Deploy ในงานนี้.
