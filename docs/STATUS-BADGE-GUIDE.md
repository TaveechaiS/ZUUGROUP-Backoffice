# มาตรฐานป้ายสถานะ ZUUGROUP

> น้ำหนักข้อความใช้ `poppins-semibold` ตาม TASK-083; สีใช้ Tailwind classes ระดับ 50/600 ตามมาตรฐานด้านล่าง.

เจ้าของยืนยัน 2026-10-02: ใช้ดีไซน์นี้กับทุกหน้าปัจจุบันและสถานะใหม่ในอนาคต.

## วิธีใช้

```tsx
import StatusBadge from '@/components/ui/status-badge';

<StatusBadge value="ร่าง" />
<StatusBadge value="ระงับการใช้งาน" />
<StatusBadge value={record.status} />
```

ใช้กับสถานะในตาราง การ์ด รายละเอียด Dashboard และ placeholder. ปุ่มaction/ตัวเลือกform/filter/ข้อความอธิบายไม่ใช่ป้ายสถานะ.

ตารางที่มีคอลัมน์สถานะต้องใช้หัวคอลัมน์ **สถานะ** (`<th scope="col">สถานะ</th>`). ภายในcellใช้StatusBadge; มุมมองdesktop/mobileต้องไม่ตกหล่น. ถ้าแสดงเป็นการ์ดมือถือแทนตารางให้มีlabelสถานะกำกับ. ตารางที่ไม่มีข้อมูลสถานะไม่ต้องเพิ่มคอลัมน์ปลอม.

## สีส่วนกลาง

| กลุ่ม | พื้น / ข้อความ | ตัวอย่าง |
|---|---|---|
| สำเร็จ/พร้อมใช้ | emerald-50 / emerald-600 | ปกติ, ใช้งานอยู่, มี, อนุมัติแล้ว |
| รอ/เตือน | orange-50 / orange-600 | รออนุมัติ, ต่ำกว่าปกติ, ใกล้หมดอายุ |
| ปิด/ผิดปกติ | red-50 / red-600 | ระงับการใช้งาน, ลบแล้ว, ต่ำผิดปกติ |
| ดำเนินการ/ข้อมูล | blue-50 / blue-600 | กำลังดำเนินการ, เตรียมโครงหน้าแล้ว |
| กลาง/ยังไม่พร้อม | slate-50 / slate-600 | ร่าง, ไม่มี, ยังไม่ระบุ |

จุดกลมใช้สีเดียวกับตัวหนังสือผ่าน bg-current. ข้อความและdotอยู่ในpillเดียว;ตัวหนังสือยาวwrapได้และdotไม่หด.

## เมื่อเพิ่มสถานะใหม่

1. ยืนยันชื่อ/ความหมายธุรกิจใน Specs ตามกติกาเดิมก่อนเพิ่มสถานะจริง.
2. เพิ่มชื่อหรือenumใน statusTones ของ src/components/ui/status-badge.tsx และเลือกหนึ่งใน5กลุ่มสี.
3. ทุกหน้าส่งvalueเข้า StatusBadge โดยไม่กำหนดสีที่หน้าเอง. ถ้าไม่มีmappingยังแสดงป้ายเทาและข้อความเดิม.
4. อย่าใช้ regexกว้างที่ทำให้ “ต่ำผิดปกติ” เป็นสีเดียวกับ “ปกติ”. ไม่เปลี่ยนlabelจริงเพื่อให้เข้าสี.
5. ตรวจหน้ารายการ/รายละเอียดและหน้าจอเล็ก;สถานะต้องมีข้อความเสมอ ไม่สื่อด้วยสีอย่างเดียว.

ไม่เขียนstatuspillใหม่ในหน้า ไม่แก้globals.cssเพิ่มรูปแบบเฉพาะ และไม่คำนวณสถานะคลังจากcomponentนี้.
