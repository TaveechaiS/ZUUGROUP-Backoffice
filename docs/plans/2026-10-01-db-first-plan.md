# แผนปรับลำดับ — โมดูลจริงบน DB พร้อมข้อมูลทดสอบ

**วันที่:** 2026-10-01 (Asia/Bangkok)
**อ้างอิง:** [ข้อกำหนดเพิ่มเติม](../specs/2026-10-01-db-first-amendment.md), Project Plan Phase 3–10, TASK-041

## ลำดับทำงาน

1. ตรวจ schema, Mock routes, Gate และ OPEN ของแต่ละโมดูล; ระบุหน้าที่เป็นระบบจริง/Mock ก่อนเปลี่ยนข้อมูล
2. ทำ Specs รายโมดูลและแผนย่อยก่อน code/migration โดยระบุฟิลด์ สิทธิ์ การลบ Audit seed ไฟล์ที่จะเปลี่ยน และ Scenario ตรวจรับ; ให้เจ้าของโครงการตรวจตาม AGENTS.md
3. เริ่ม **ข้อมูลหลักสินค้า** ที่กติกาชัดและไม่เปลี่ยนยอดเงิน/คลัง: ทำการเพิ่ม ดู แก้ ค้นหา/กรอง และลบ/กู้คืนตามสิทธิ์ที่ยืนยัน พร้อม audit และ seed ที่รันซ้ำได้; รหัสสร้างจากหมวดหมู่-รูปแบบยา-เลขลำดับ 4 หลักตาม Specs สินค้า
4. ขยายข้อมูลหลักอีกโมดูล ผู้ขาย และค่าใช้จ่ายเฉพาะส่วนที่ข้อกำหนดครบ; เชื่อมความสัมพันธ์ด้วย ID ภายในคงเดิม
5. ทำ Stock/Lot/รับเข้า/โอน/จ่ายเมื่อ G-07 และคำถามที่เกี่ยวข้องปิด; ทุกยอดต้องมี transaction และ ledger
6. ทำใบเสนอราคา/คำสั่งซื้อ/อนุมัติ/โปรโมชันตาม G-05–07; ทำการเงินตาม G-08; ทำไฟล์/Audit/Archive ตาม G-10; ทำ PDF/รายงานตาม G-09 และข้อมูลต้นทางที่ผ่านตรวจ
7. ทุกโมดูลตรวจ migration, RLS/สิทธิ์ Server, กรณีข้อมูลซ้ำและคำขอพร้อมกัน, audit, seed ซ้ำ, lint/type-check/build และ UAT ก่อนเปลี่ยนสถานะจาก Mock เป็นจริง

## งานแรกหลังแผนนี้

- จัดทำ Specs และ Task สำหรับข้อมูลหลักสินค้า; ห้ามเริ่ม migration ก่อนยืนยันการเชื่อม ID ยา/คลัง, รูปแบบรหัสและสิทธิ์ที่จำเป็น
- ไฟล์ที่จะเปลี่ยนในงานแรกจะระบุในแผนย่อยรายโมดูล ไม่เหมารวมทุก route เป็นหนึ่ง Task
- ข้อมูลใน browser session ของ Mock เดิมไม่ใช่ข้อมูลจริงและไม่ย้ายอัตโนมัติ; seed DB ใช้ข้อมูลตัวอย่างที่ระบุใน Specs งานนั้น

## วิธีตรวจรับแผน

เจ้าของโครงการตรวจว่าลำดับโมดูลแรก, ขอบเขตข้อมูลจริง และรายการที่รอกฎตรงกับการใช้งานที่ต้องการ ก่อนเปิด Task เขียน migration/API ของโมดูลแรก
