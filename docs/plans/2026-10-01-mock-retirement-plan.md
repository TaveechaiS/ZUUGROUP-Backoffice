# แผนย่อย TASK-044 — สำรวจและจัดลำดับย้าย Mock ไป DB

**สถานะ:** DRAFT — รอคำตอบเรื่องขอบเขตและการ seed
**ผลลัพธ์:** รายการหน้า Mock, ลำดับงานที่ตรวจรับได้ และเงื่อนไขก่อนเปิด Task เขียน DB

## ลำดับ

1. ตรวจ `tasks/ACTIVE.md`, Specs/Plan DB-first, schema Prisma, หน้า Mock และตัวเก็บ `sessionStorage`; แยกหน้าที่ DB แล้วออกจากหน้าที่ยัง Mock
2. บันทึกข้อกำหนดการยกเลิกตัวเลข/รายการแต่งขึ้น และรายการที่ต้องรอกฎธุรกิจใน [ร่าง Specs](../specs/2026-10-01-mock-retirement.md)
3. รับคำตอบเจ้าของโครงการเรื่องขอบเขตและข้อมูลตัวอย่างที่จะ seed; ปรับ Specs หลักและ Plan หลักให้ตรงกันก่อนเปิดงานโค้ด
4. เปิด Task รายโมดูลพร้อม Specs เฉพาะ: ฟิลด์บังคับ รหัส สถานะ คำสั่ง Role/ขอบเขตข้อมูล ลบ/กู้คืน Audit seed และ UAT; ขออนุมัติก่อน migration/API/UI
5. ลำดับที่เสนอ: อ่าน Audit จาก DB ที่มีอยู่ → ตัดตัวเลข Dashboard ที่ไม่มีต้นทางและใช้เฉพาะ metric ที่นิยามได้ → ข้อมูลหลักผู้ขาย → ข้อมูลลูกค้า → ธุรกรรมคลัง/ขาย/จัดซื้อ/การเงิน → รายงาน โดยข้ามส่วนที่พึ่ง OPEN จนกว่าจะได้คำตอบ
6. ในแต่ละโมดูล ทดสอบ migration/query, RBAC, seed ซ้ำ, lint/type-check/build และ UAT; ลบ Mock code/data เฉพาะเมื่อไม่มีผู้อ้างอิงแล้ว
