# ตรวจหน้าต่างยืนยันและ SuccessAlert — TASK-063

ใช้ Admin กับข้อมูลทดลอง. คำว่า “ผ่าน” ต้องบันทึกหลังลองหน้าจอจริง; static checks ไม่แทนการทดสอบนี้. ไม่มีรหัสผ่าน/token จริงในคู่มือ. ระบบไม่ใช้ browser alert/confirm แบบ localhost says แล้ว.

## ทุกปุ่มใช้เกณฑ์เดียวกัน

ระหว่างรอ server ปุ่มไม่ทำซ้ำ; สำเร็จแล้วมี SuccessAlert หนึ่งครั้งพร้อมข้อความตรง action. กรณีที่ต้องนำทาง (เพิ่มรายการ/ลบรายการ/เปลี่ยนรหัสพนักงาน) ต้องรอปิดก่อน. หลังปิดและ refresh ข้อมูลยังตรงกับสิ่งที่บันทึก.

Shared CRUD ต้องลองเส้นทาง customers, customer-groups, sales-territories, customer-documents, customer-follow-ups, suppliers, expenses, purchases, quotes, orders, billing, promotions, stock-counts, settings. การติดตามลูกค้าอยู่ /customers/dashboard; metadata เลือกเส้นทางหน้าให้เอง. ใช้รายการใหม่และยืนยันผลก่อนทำรายการถัดไป.

## ยืนยันบันทึกการแก้ไข (เพิ่มเติมตามคำท้วง)

ลองแก้ในรายละเอียดข้อมูลรายโมดูล, สินค้า และข้อมูลบัญชีผู้ใช้: กดบันทึก → modal ของเว็บปุ่มสีน้ำเงิน “ยืนยันบันทึก”. กดยกเลิก/X/Escape/พื้นหลัง → ไม่ส่ง PATCH, ค่าที่แก้ยังอยู่ในฟอร์ม. ยืนยัน → กำลังบันทึก, กดซ้ำไม่ได้ → สำเร็จปิด confirmation แล้วแสดง SuccessAlert. Error ไม่มี success และค่าคงอยู่ให้แก้/ลองใหม่. เปลี่ยนรหัสพนักงานแล้ว URL ใหม่เกิดหลังปิด SuccessAlert.

## ขั้นตอนยืนยันลบ

1. กดลบ → เห็นหน้าต่างเว็บ มีชื่อรายการและปุ่มยกเลิก/ยืนยันลบ.
2. ยกเลิก, X, Escape หรือคลิกพื้นหลัง → ไม่ลบและไม่มี success.
3. ยืนยันลบ → ปุ่มแสดงกำลังลบ; ปิด/ยืนยันซ้ำไม่ได้ขณะรอ. สำเร็จปิด confirmation ก่อนเปิด SuccessAlert; ล้มเหลวกลับหน้าเดิมมี error.
4. Tab/Shift+Tab อยู่ในหน้าต่าง; เริ่ม focus ที่ยกเลิก. หลังยกเลิกกลับไปปุ่มเดิม. ทดลองหน้าจอมือถือและ reduced motion.

## ป้องกันแจ้งสำเร็จผิด

- กรอกไม่ครบหรือรหัสซ้ำ: ไม่มี SuccessAlert; validation/error ชัดเจน.
- ยกเลิกลบ: ไม่มี mutation และไม่มี success.
- กด/Enter ซ้ำขณะรอ: ไม่มีรายการซ้ำหรือ dialog ซ้อน.
- สิทธิ์ไม่พอ: API ปฏิเสธ ไม่มี success.
- ตัดเครือข่ายก่อนส่งข้อมูลทดลอง: แสดง error. หาก response หายกลางคำขอ อาจบันทึกไปแล้ว ให้ตรวจรายการก่อนลองซ้ำ.
- ค้นหา/filter/เปิดหน้า: ไม่มี SuccessAlert.

ทดสอบบัญชีด้วยผู้ใช้ทดลองที่ไม่ใช่ตัวเองหรือ Admin คนสุดท้าย. ไม่ลบ/ระงับบัญชีที่ใช้ทำงานจริงเพื่อทดสอบ.
