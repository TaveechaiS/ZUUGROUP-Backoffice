Role และสถานะถูกอ่านจากฐานข้อมูลทุกคำขอที่มีข้อมูลหรือการเปลี่ยนแปลงจริง ผู้ถูกระงับและผู้ไม่มี Role ถูกปฏิเสธ แม้ยังถือ Session เดิมอยู่ เมนูธุรกิจอื่นใน Phase 1–2 เป็นหน้าแสดงตัวอย่าง; สิทธิ์อ่าน/เขียนข้อมูลจริงของแต่ละโมดูลต้องกำหนดใน Specs รายโมดูลก่อนเปิด API นั้น

Role ที่ใช้มีสี่รายการตามตารางเท่านั้น ไม่มี Role Inventory. บัญชีหนึ่งมีหนึ่ง Role (`user_roles.user_id` เป็นคีย์หลัก). การลด Role หรือระงับ Admin คนสุดท้ายถูกปฏิเสธใน Transaction ที่ถือ advisory lock เดียวกัน
