# ร่างข้อกำหนด — ยกเลิกข้อมูล Mock และย้ายหน้าไปใช้ DB

**วันที่:** 2026-10-01 (Asia/Bangkok)  
**สถานะ:** DRAFT — รอเจ้าของโครงการตรวจขอบเขตและอนุมัติ Task รายโมดูล  
**อ้างอิง:** [Project Specs](2026-09-23-1550-project-specs.md), [DB-first](2026-10-01-db-first-amendment.md), คำขอเจ้าของโครงการให้ลบข้อมูล Mock และย้ายไป DB

## สภาพปัจจุบัน

- `/users` และ `/products` อ่าน/เขียน DB แล้ว; สินค้าตัวอย่าง 2 รายการเป็นแถวจริงใน DB พร้อม `is_sample` และไม่มียอดสต็อก; `/audit-logs` อ่าน `audit_events` จริงแล้วตาม TASK-045
- หน้า Dashboard ใช้ตัวเลขและเหตุการณ์ที่เขียนไว้ใน `src/app/data.ts`
- หน้ารายการ 18 URL ยังอ่านข้อมูลที่เขียนไว้ใน `data.ts` ของแต่ละหน้า; ตัวช่วย `createMockConfig` ทำซ้ำรายการจนเป็น 30 แถวต่อหน้า
- หน้า `/create` ที่คู่กับรายการ Mock บันทึกชื่อไว้ใน `sessionStorage` ของแท็บ ไม่สร้างข้อมูลใน DB; `/customers/[ref]` อ่านข้อมูล Mock แบบเดียวกัน
- DB ปัจจุบันมีโมเดลผู้ใช้/สิทธิ์/Audit และข้อมูลหลักสินค้า/หมวด/รูปแบบยา/ตัวยา/คลัง ยังไม่มีตารางลูกค้า ผู้ขาย ค่าใช้จ่าย เอกสารขาย/ซื้อ การเงิน Lot หรือ Stock Ledger

## ความหมายของการย้าย

1. หน้าใดเปลี่ยนเป็น DB ต้องอ่านจากตารางจริง และคำสั่งสร้าง/แก้/ลบต้องผ่าน Server validation, RBAC และ Audit ตามชนิดข้อมูลนั้น; เลิกพึ่ง `src/features/mock/*` และ `sessionStorage` เฉพาะหน้านั้น
2. ลบเลขยอดและสถานะที่แต่งขึ้นจากหน้าใช้งานจริง ถ้ายังไม่มีข้อมูลต้นทางหรือสูตรที่อนุมัติ ให้แสดงสถานะว่ายังไม่มีข้อมูลหรือยังไม่พร้อม ไม่แสดงเลขสมมุติเป็นยอดจริง
3. ข้อมูลตัวอย่างที่ต้องมีใน DB ให้ seed ซ้ำได้โดยไม่ทับข้อมูลผู้ใช้และติดป้าย `is_sample` หรือวิธีเทียบเท่า; ห้ามแปลงแถว Mock ที่ไม่มีฟิลด์บังคับให้เป็นธุรกรรมจริงด้วยค่าเดา
4. รายการใน `sessionStorage` ของผู้ใช้แต่ละแท็บไม่ย้ายอัตโนมัติ; ต้องกำหนดวิธีนำเข้าหากต้องรักษารายการเหล่านั้น
5. หน้า Mock ที่ยังไม่มี Specs รายโมดูลคงระบุว่าเป็นตัวอย่างชัดเจนจนกว่าจะเปลี่ยนเสร็จ ห้ามลบป้าย Mock แล้วปล่อยให้ข้อมูลแต่งขึ้นดูเป็นข้อมูลจริง

- ย้ายทีละโมดูลตามกฎที่ยืนยันแล้ว หรือขอวาง schema ทุกโมดูลในรอบเดียว

- Specs/Task รายโมดูลต้องอนุมัติก่อนเขียน schema/API/UI ตาม AGENTS.md ข้อ 3 และแผน DB-first ที่ยืนยันไว้
