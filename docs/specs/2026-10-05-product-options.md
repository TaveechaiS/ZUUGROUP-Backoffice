# TASK-151 — รายการกลางสินค้าในตั้งค่าระบบ

อนุมัติ5ตุลาคม2569 จาก “ok ทำและเพิ่มข้อมูลให้ด้วย”.

## ขอบเขตและพฤติกรรม

- `/settings` แสดงทางเข้าข้อมูลพื้นฐานสินค้า โดยยังไม่เปิดหน้าตั้งค่าทั่วไปเดิมที่ถูกพัก. `/settings/product-options` มี10ชุด: codeGroupกลุ่มรหัส, codeFormatรูปแบบรหัส, productTypeประเภทผลิตภัณฑ์, categoryหมวดหมู่, brandยี่ห้อ, manufacturerบริษัทผู้ผลิต, ingredientตัวยาสำคัญ, dosageFormรูปแบบยา, legalTypeประเภทตามกฎหมาย, unitหน่วย.
- Adminเท่านั้นจัดการข้อมูล. ผู้อื่นที่เข้าสู่ระบบอ่านเฉพาะรายการที่เปิดให้เลือกได้ ไม่มีเพิ่ม/แก้ไข/ปิดรายการ. หน้าตั้งค่าrequireAdminและAPIตรวจroleจากผู้ใช้จริง.
- เพิ่มรายการ แก้ชื่อ ปิด/เปิดได้ ไม่มีลบถาวร. ชื่อซ้ำในชุดเดียวกันไม่อนุญาต(case/ช่องว่าง) รหัสกลุ่ม/รูปแบบ/หมวดและรูปแบบยา2–3ตัวอักษรA-Z0-9และไม่ซ้ำในชุด. แก้ไขรหัส/ชนิดไม่ได้. มีversionกันแก้ทับพร้อมกัน ใช้audit transaction.
- ใช้product_optionsกลาง ชุดcategory/dosageForm/ingredientอ้างUUIDเดียวกับlegacy tablesและแก้ชื่อพร้อมกันในtransaction เพื่อไม่ตัดFKของสินค้าที่มีอยู่. ปิดรายการเพียงไม่ให้เลือกใหม่ ไม่แก้สถานะสินค้า/สต็อกเดิม. ชุดอื่นไม่ผูกกับสินค้าเก่าที่ไม่มีช่องรองรับ.
- ฟอร์มเพิ่มสินค้าใช้Comboboxกลางค้นหา/คีย์บอร์ด/โหลดเพิ่ม เลือกข้อมูลจากAPI ไม่มีเพิ่มในdropdown/localStorage. หากไม่พบ Adminเห็นลิงก์ตั้งค่าชุดนั้นในแท็บใหม่ พร้อมrefreshรายการเมื่อกลับหน้า ไม่ล้างข้อมูลช่องที่กรอก. แสดงเฉพาะรายการเปิด; ถ้ารายการที่เลือกถูกปิดแจ้งให้เลือกใหม่. รูปแบบรหัสและรูปแบบยาแยกชุดกัน; ยังไม่สร้าง/รันรหัสหรือบันทึกสินค้า.

## API contract

`GET /api/product-options?kind=brand&search=&limit=50&offset=0`: sessionเดิม, คืน `{data: [{id,kind,name,code,active,version}], pagination:{total,limit,offset}}`. kindต้องเป็นหนึ่งใน10ชุด limit1–100 offset>=0. เริ่มอ่านเฉพาะactive; `includeInactive=true`สำหรับAdminหน้าตั้งค่าเท่านั้น. ไม่cacheข้อมูลส่วนตัว.

รองรับ `id=UUID` สำหรับตรวจรายการที่เลือกเมื่อกลับจากตั้งค่า ถ้าปิดแล้วได้dataว่างให้pickerล้างIDและแจ้งเลือกใหม่ ถ้าแก้ชื่อได้ชื่อใหม่โดยคงIDเดิม.

`POST /api/product-options`: Admin/same-origin JSON `{kind,name,code?}` คืน201 `{item}`. `PATCH`: `{id,version,name?,active?}` คืน200 `{item}`. แก้code/kindไม่ได้. 400ข้อมูลผิด,401ไม่เข้าสู่ระบบ,403ไม่มีสิทธิ์/cross-origin,404ไม่พบ,409ชื่อ/รหัสซ้ำหรือversionเก่า,503DBเชื่อมไม่ได้. ไม่มีDELETE.

## ข้อมูลเริ่มต้น

ผลลงDBจริง40รายการใน10ชุด คงสินค้าเดิม12รายการและยอด950หน่วย. Seedรันซ้ำไม่แก้ชื่อ/สถานะ/versionของรายการที่มีอยู่แล้ว.

นำcategory/dosage_forms/drugsปัจจุบันเข้ารายการกลางโดยคงUUID/ชื่อ/รหัส. เติมcodeGroup MED/HER/SUP, codeFormat TAB/CAP/SYR/OTH แยกชุด, productTypeยา/สมุนไพร/อาหารเสริม/เครื่องสำอาง/เครื่องมือแพทย์, หน่วยเม็ด/แคปซูล/ขวด/กล่อง/หลอด/ซอง/ชิ้น/ลัง. brand/manufacturerเป็นชื่อตัวอย่างชัดเจน ไม่อ้างว่าเป็นผู้ผลิตจริง. legalTypeเริ่ม “ยังไม่ระบุ / รอตรวจสอบ” ไม่ใส่ประเภทกฎหมายให้ยาโดยเดา. Seedไม่เขียนทับรายการที่Adminแก้/ปิดและไม่เปลี่ยนสินค้า/ยอด950หน่วย.

DBตารางใหม่เปิดRLSและrevoke anon/authenticated ใช้server APIเดิมเป็นทางเข้า ไม่เพิ่มpolicyเปิดข้อมูลตรงจากเบราว์เซอร์.

## ⚠️ ต้องทดสอบโดยคุณ

Adminเปิดตั้งค่าระบบ→ข้อมูลพื้นฐานสินค้า เห็น10ชุด เพิ่ม/แก้ชื่อ/ปิด/เปิดแล้วrefreshยังอยู่. เพิ่มชื่อหรือรหัสซ้ำต้องแจ้งerrorไม่เพิ่มซ้ำ. หน้าเพิ่มสินค้าค้น/เลือกในทุกComboboxได้ ไม่มีเมนูเพิ่มใหม่ รายการปิดไม่แสดงและสินค้าเดิมยังอยู่. ไม่พบรายการเปิดตั้งค่าแท็บใหม่ กลับหน้าฟอร์มข้อมูลเดิมยังอยู่และรายการใหม่ค้นเจอ. ผู้ไม่ใช่Adminเข้าAPIจัดการต้อง403. ปุ่มบันทึกสินค้าเป็นpreviewตามเดิม.
