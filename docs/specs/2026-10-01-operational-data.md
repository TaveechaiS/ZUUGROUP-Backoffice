# TASK-052 — ข้อมูลตั้งต้นของระบบจริง

วันที่ 2026-10-01; สถานะ: เจ้าของอนุมัติ Specs/Task แล้ว

## ข้อกำหนดใหม่จากเจ้าของ

เจ้าของแก้ขอบเขต TASK-051: ไม่แยก Mock/Demo ให้ลงตารางของระบบจริง ใช้ข้อมูลที่มีและฟิลด์หลักก่อน เพิ่มลดในชุดเดียวภายหลัง ไม่ทำระบบข้อมูลสองชุด. ยกเลิกแนวทางใช้ demo_datasets/demo_rows เป็นแหล่งข้อมูลหลัก; การเปลี่ยนชื่อโฟลเดอร์หรือข้อความอย่างเดียวไม่ถือว่าครบงาน

## ตารางและข้อมูลหลัก

ทุกข้อมูลใช้ UUID ภายในคงเดิม, รหัสอ้างอิงไม่ซ้ำภายในโมดูล, createdAt/updatedAt, ลบเชิงตรรกะและกู้คืน. นำเข้าข้อมูลเดิมเฉพาะส่วนที่มีจริง ไม่สร้างวันที่ ปี ยอด หรือความสัมพันธ์ที่ไม่มีต้นทาง. ผู้ดูแลชื่อเดิมเก็บเป็นข้อความนำเข้าหากจับคู่ User ไม่ได้ ไม่สร้างบัญชีปลอม

| โมดูล/ตาราง | ฟิลด์หลักรอบแรก |
|---|---|
| ลูกค้า / Customer | รหัส, ชื่อ, ประเภท, จังหวัด, ผู้ดูแล, เงื่อนไขชำระ, สถานะ, หมายเหตุ |
| กลุ่มลูกค้า / CustomerGroup | รหัส, ชื่อ, คำอธิบาย, ผู้ดูแล, สถานะ; จำนวนลูกค้านับจากความสัมพันธ์ |
| เขตขาย / SalesTerritory | รหัส, ชื่อ, พื้นที่, ผู้ดูแล, สถานะ |
| เอกสารลูกค้า / CustomerDocument | รหัส, customerId, ชื่อ/ประเภทเอกสาร, ข้อความวันที่เดิม, สถานะ; URL ไฟล์ว่างได้ |
| ติดตามลูกค้า / CustomerFollowUp | customerId, ข้อความติดตาม, สถานะ; แยกจากสถานะบัญชีลูกค้า |
| ผู้ขาย / Supplier | รหัส, ชื่อ, ประเภท, รายละเอียด, ผู้ดูแล, เงื่อนไข, สถานะ |
| ค่าใช้จ่าย / Expense | เลขอ้างอิง, ชื่อ, หมวด, รายละเอียดเดิม, ผู้บันทึก, จำนวนเงินที่อ่านได้ตรงจากต้นทาง, สถานะ |
| จัดซื้อ / PurchaseOrder | เลขเอกสาร, supplierId เมื่อจับคู่ได้แน่นอน, รายละเอียด, ผู้ดูแล, จำนวนเงินจากต้นทาง, สถานะ |
| ใบเสนอราคา / Quotation | เลขเอกสาร, customerId, รายละเอียด, ผู้ดูแล, จำนวนเงินจากต้นทาง, สถานะ |
| คำสั่งซื้อ / SalesOrder | เลขเอกสาร, customerId, รายละเอียด, ผู้ดูแล, จำนวนเงินจากต้นทาง, สถานะ |
| วางบิล / Invoice | เลขเอกสาร, customerId, รายละเอียดครบกำหนดเดิม, ยอดจากต้นทาง, ผู้ดูแล, สถานะ |
| โปรโมชั่น / Promotion | รหัส, ชื่อ, รายละเอียด, ผู้ดูแล, เงื่อนไขเดิม, สถานะ |
| ตรวจนับ / StockCountSession | เลขอ้างอิง, ชื่อ, รายละเอียด, ผู้บันทึก, ข้อความผลเดิม, สถานะ; ไม่สร้าง Ledger/ปรับยอด |
| ตั้งค่า / SystemSetting | รหัส, ชื่อ, คำอธิบาย, ค่าเดิม, ผู้ดูแล, สถานะ; ไม่ให้ข้อมูลเดิมเปลี่ยนสิทธิ์ Auth หรือเลขเอกสารอัตโนมัติ |

สินค้า/หมวดสินค้า/รูปแบบยา/ตัวยา/คลัง/ผู้ใช้/Audit ใช้ตารางจริงที่มีอยู่แล้ว. รายการเอกสารรอบนี้เป็นข้อมูลหัวเอกสารและยอดที่เจ้าของยอมรับเป็นข้อมูลตั้งต้น ยังไม่สร้างบรรทัดสินค้าหรือคำนวณ VAT/ส่วนลด/ชำระเงิน/สต็อกจากข้อความ

## การรวมและย้ายข้อมูล

- customers และ customers/list ใช้ Customer ชุดเดียว รวมด้วยรหัสเดิม ไม่เพิ่ม CUS-1001 ถึง CUS-1003 ซ้ำ
- customers/dashboard ใช้ CustomerFollowUp; ลูกค้า CUS-1005 เพิ่มจากข้อมูลที่มี ไม่ทับสถานะ Customer ด้วยสถานะงานติดตาม
- เอกสารเชื่อมลูกค้า/ผู้ขายด้วยชื่อหรือรหัสที่ตรงแน่นอนเท่านั้น; หากไม่ตรงให้เก็บข้อความคู่ค้าเดิมและ FK ว่าง เพื่อให้ Admin เลือกแก้ได้
- Dashboard activity เดิมเชื่อมเอกสารตาม ref ไม่สร้างหัวเอกสารซ้ำ. เวลา 09:42 ที่ไม่มีวันครบเก็บเป็นข้อความเดิม ไม่เดา timestamp
- เก็บ UUID เดิมเมื่อรายการไม่ซ้ำ; รายการที่ถูกรวมมี mapping เดิมไป ID หลักสำหรับลิงก์อ้างอิง
- ข้อมูลกลุ่ม/เขตที่บอก 32/48/76 ราย แต่ไม่มีลูกค้าต้นทางไม่ใช้เป็นจำนวนจริง. ยอดรายงาน/metrics/กราฟเดิมที่ไม่ตรงข้อมูลต้นทางไม่ย้ายเป็นยอดจริง
- นำเข้าภายใน transaction, ตรวจจำนวน/mapping ก่อนถอนตาราง demo; มี migration ย้อนรอยและไม่ลบข้อมูลผู้ใช้/สินค้าที่มีอยู่

## API/UI/Postman

- API ใช้ชื่อโมดูลจริง เช่น /api/customers, /api/customer-groups, /api/sales-territories, /api/suppliers, /api/quotes, /api/orders, /api/billing; ไม่มี prefix /demo หรือโฟลเดอร์ Demo ใน Postman
- GET list/detail/filters แยกเส้น, default limit 10/max50, offset/search/status/owner/category ตามฟิลด์โมดูล; pagination/query ใน DB
- เพิ่ม POST/PATCH/DELETE และ restore สำหรับข้อมูลพื้นฐานที่กำหนดแล้ว พร้อม validate, ตรวจรหัสซ้ำ, transaction และ audit. Admin จัดการข้อมูลตั้งต้น; หน้าเว็บของ Role อื่นอ่านตามสิทธิ์เดิมของโมดูล
- GET ใน Postman ใช้ No Auth ตามคำสั่งเจ้าของเดิมและตอบเฉพาะฟิลด์ที่เปิดไว้แล้ว; ห้ามเปิดข้อมูล User/Auth/Audit/secret ผ่านการย้ายนี้. คำขอเขียนตรวจ session/Bearer และสิทธิ์ Admin; Postman เก็บ login/token ตามระบบที่มีอยู่ ไม่ใส่ secret/password จริงในไฟล์. การนำข้อมูลจริงใหม่ที่มีฟิลด์เพิ่มเข้าระบบต้องกำหนดรายการฟิลด์ GET ก่อนเปิดฟิลด์นั้น
- หน้า list/detail/create/edit ใช้ตารางเดียวกับ API, เปิดการบันทึกจริงสำหรับฟิลด์พื้นฐาน; ไม่แสดงข้อความ Mock/Demo/ข้อมูลจำลอง และไม่มี sessionStorage เป็นฐานข้อมูล
- Dashboard/รายงานอ่านข้อมูลต้นทาง. รอบแรกแสดงรายการ/จำนวนที่ตรวจสอบได้; ยอดขายรับรู้ ลูกหนี้สุทธิ Lot คงเหลือ และเงินสดที่ยังไม่มีกฎ/ข้อมูลครบให้แสดง “ยังไม่มีข้อมูล” ไม่มีตัวเลขเดา

## ขอบเขตที่ยังรอข้อกำหนดเดิม

## คำขอเพิ่มข้อมูลทุกโมดูลระหว่างดำเนินงาน

เจ้าของขอเพิ่มข้อมูลทุกอย่างลง DB ใน Task นี้. เติมข้อมูลตั้งต้นให้ตารางหลัก/หัวเอกสาร 14 ตารางและสินค้าอย่างน้อย 15 รายการที่ยังไม่ลบ เพื่อเห็น pagination; เติมข้อมูลแม่สินค้าให้เลือกได้. ใช้รหัสข้อมูลตั้งต้นที่ไม่ซ้ำกับเอกสารเดิม, FK เป็น ID จริง, สถานะหัวเอกสารใหม่เป็นร่าง, ไม่เดาวันอนุมัติ/ชำระ/จัดส่งและไม่สร้างยอดคลัง. ยอดที่ยังไม่มีให้ว่าง แก้ในฟอร์มได้. Seed รันซ้ำไม่ทับรายการเดิมและ audit ในฐานะระบบ. Dashboard/รายงานอ่านต้นทาง ไม่ seed ยอดรวมแยก. บัญชีล็อกอินเดิมคงใช้ระหว่างรอคำตอบ ไม่เพิ่มบัญชีหรือรหัสผ่านโดยเดา

การอนุมัติเอกสาร, สูตรยอดสุทธิ/ภาษี, รับชำระ, จ่าย/รับ/โอนสินค้า, Lot, Ledger และการปรับยอดตรวจนับยังอยู่ OPEN. การอนุมัติ Task นี้ให้จัดเก็บ/จัดการข้อมูลตั้งต้นและหัวเอกสาร ไม่ใช่อนุมัติให้เดากฎเหล่านี้
