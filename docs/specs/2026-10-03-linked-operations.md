# TASK-092 เชื่อมข้อมูลและงานธุรกิจ

สถานะ: APPROVED จากคำสั่ง “ปรับทั้งหมดนี้ก่อน ทำข้อมูลและเว็บในทีเดียว” และอนุญาตค้น/เลือกแนวทางอายุยา.

## ขอบเขตที่ทำ

- เขตมี Manager/Sales อย่างละไม่เกินหนึ่ง คนละหนึ่งเขต เลือกจากบัญชีจริงตาม Role; สร้างเขตว่างได้ มีเขตเริ่มต้นเหนือ/ออก/ตก/ใต้. ลูกค้าเลือก/เปลี่ยนเขต แสดงชื่อและข้อมูลผู้รับผิดชอบ. ไม่เพิ่มสิทธิ์แยกข้อมูลรายเขต.
- ลูกค้าใหม่ต้องเลือกเขต ข้อมูลเก่าที่ไม่มีเขตเก็บไว้ให้ Admin เติมภายหลัง. ผู้ใช้ที่ยังผูกเขตต้องนำออกจากเขตก่อนลบหรือเปลี่ยนบทบาท เพื่อไม่ให้ผู้รับผิดชอบผิด Role; การระงับบัญชียังคงใช้กติกาเดิม.
- ลูกค้าเหลือกลุ่มลูกค้าช่องเดียวจาก category เดิม ไม่มี groupId ในฟอร์ม/ตัวกรองใหม่. รักษาค่าและตารางเก่าเพื่อไม่ลบข้อมูล; เติม category จากชื่อกลุ่มเดิมเฉพาะค่าที่ว่าง. ซ่อนหน้ากลุ่มแยกและเปลี่ยนไปใช้รายชื่อลูกค้า.
- รับเข้ามีหลายล็อต แต่สร้าง Lot ID ใหม่เสมอ ไม่รับเพิ่มล็อตเดิม. ต้นทุนเป็นยอดรวมล็อต Decimal; Admin/CFO เท่านั้นเห็น API/UI. เก็บแหล่งที่มา optional จำนวน วันผลิต วันหมดอายุ คลัง ผู้ทำและรายการรับเข้า. default คลังหลัก. ไม่เติมยอดตัวอย่างจากข้อมูลหลักสินค้า.
- มี balances แยก Lot/คลัง, movement อ้างต้นทาง/ผู้ทำ/เวลา, รับเข้า/โอน/ปรับยอด/แจกเป็น transaction; ตรวจนับยังไม่ปรับยอดอัตโนมัติ.
- แก้ข้อมูลรับเข้าภายใน 7*24 ชั่วโมงจากสร้างต้นฉบับ เก็บ revision พร้อมเหตุผล รักษา Lot ID และต้นฉบับ/รายการต่อเนื่องไม่ซ้ำยอด. ไม่รีเซ็ตหน้าต่างแก้. กรณีจำนวนใหม่ต่ำกว่าจ่ายแล้ว+จองต้องแจ้งปฏิเสธเพราะขัดของจริง. ไม่ยกเลิกใบขายตามไปเอง; ประวัติ cost เดิมที่จ่ายเก็บ snapshot.
- Orders: Sales สร้าง, Manager ตรวจ/ปรับ/อนุมัติ, Admin ตรวจ/จัด/ยืนยันเสร็จสิ้นตัดคลัง. กรองตามบทบาทของคำสั่งเหล่านี้เท่านั้น ไม่สร้างสิทธิ์รายเขตใหม่. สร้างจองทันที ของไม่พอสร้างไม่ได้; ใช้ FEFO อัตโนมัติเพราะเจ้าของอนุมัติให้ทำทั้งหมดตามแนวทางเสนอ. ส่งกลับเก็บจองไว้ เมื่อแก้รายการคำนวณจองใหม่และต้องผ่านอนุมัติใหม่. ยกเลิกก่อนเสร็จสิ้นคืนจองพร้อมเหตุผล; เสร็จสิ้นไม่ลบผ่าน generic CRUD.
- Orders เดิมที่มีแต่หัวเอกสารแสดงอ่านได้และระบุไม่มีรายการล็อต ไม่สร้างจอง/ขายสมมติจากยอดเงินเดิม.
- ราคาขาย snapshot ในรายการขายจากราคาหลัก Admin ไม่มีปรับตามต้นทุน. Manager ปรับสินค้า/จำนวน/หมายเหตุเอกสารได้ ไม่เปลี่ยนราคาหลัก. รายการเสร็จสิ้นเก็บราคา/ต้นทุนขณะจ่ายเพื่อประวัติ ไม่อ้างกำไรสุทธิ.

## อายุสินค้า (เลือกตามที่เจ้าของมอบหมาย)

- FEFO เฉพาะล็อตคลังต้นทางที่ยังใช้ได้. ขายเหลืออย่างน้อย 6 เดือนปฏิทิน ณ วันจัดของ เป็นนโยบายบริษัทเริ่มต้นที่ปรับได้ ไม่อ้างว่าเป็นกฎหมายสากล. วันหมดอายุระบุเดือน/ปีต้องกรอกวันสุดท้ายของเดือนตามฉลาก; UI กรอกวันจริง.
- บริจาคตั้งค่าเริ่มต้นอย่างน้อย 12 เดือน ณ วันที่คาดว่าผู้รับได้รับ; ต้องมีผู้รับและ Admin ยืนยันตรวจเงื่อนไขผู้รับ/สภาพยา. แจกทั่วไปแยกจากบริจาค; ไม่ถือว่าย้ายคลังทำให้แจกได้โดยอัตโนมัติ. ของเสื่อม/หมดอายุถูกบล็อกขาย/แจกและเสนอคลังรอทำลาย.
- 90 วันเป็นคำเตือนเดิมเพิ่มเติมจากเกณฑ์งดขาย; ไม่มี background job ย้ายยอดเอง. Admin โอนพร้อมเหตุผลเมื่อย้ายจริง เก็บ Lot ID เดิมและจำนวนจองห้ามโอนทับ.
- อ้างอิง: [WHO medicine donations](https://www.who.int/publications/i/item/9789241501989), [WHO guideline PDF](https://iris.who.int/bitstream/handle/10665/44647/9789241501989_eng.pdf), [อย. ยาหมดอายุและเสื่อมสภาพ](https://www.fda.moph.go.th/news/เตือนภัยยาหมดอายุยาเสื่อมสภาพ), [Microsoft FEFO](https://learn.microsoft.com/en-us/dynamics365/business-central/warehouse-picking-by-fefo).

## API contract

- `/api/inventory`: GET `view=stock|receipts|movements|options`, offset/limit/search; POST actions `receive|correct|transfer|adjust|give`. ใช้ idempotencyKey ของคำสั่งเพื่อกัน submit ซ้ำ. cost ไม่อยู่ใน response ของ Role อื่น.
- `/api/orders`: GET list, `view=options` และ detail; POST สร้าง `{code,customerId,notes,lines:[{productId,quantity}],idempotencyKey}`. `/api/orders/{id}` PATCH `{action:approve|return|edit|complete|cancel,reason?,lines?,notes?,expectedUpdatedAt?,idempotencyKey}`. DELETE แปลงเป็น cancel ก่อนเสร็จสิ้นเท่านั้น ไม่ซ่อนแล้วปล่อยจองค้าง. ไม่ใช้ config/filters ของหัวเอกสารเดิม.
- `/api/sales-territories`: เพิ่ม managerId/salesId; config/options/CRUD เดิม. `/api/inventory?view=options` ส่งผลิตภัณฑ์/คลัง/ลูกค้า/actor และ users สำหรับ Admin เท่านั้น.
- error รูปแบบ `{error:{message}}`; ทุกคำสั่ง try/catch ตรวจข้อมูล/บทบาท/สถานะและเก็บ Audit. RLS เปิดตารางใหม่ ไม่มี grant anon/authenticated เพื่อไม่ข้าม API.

ส่วนยังไม่ทำ: ภาษี/ส่วนลด/เครดิต/ใบแจ้งหนี้จริง, ทำลายจริง, return ขายหลังเสร็จสิ้น, Dashboard API redesign, ข้อมูลผู้จำหน่ายละเอียด. ไม่ปล่อยเส้นทาง generic ให้แก้สถานะ/ยอด Orders ใหม่ข้าม workflow.
