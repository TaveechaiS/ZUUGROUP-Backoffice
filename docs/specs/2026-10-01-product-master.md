# ข้อกำหนดงานย่อย — ข้อมูลหลักสินค้าใน DB

**วันที่:** 2026-10-01 (Asia/Bangkok)
**สถานะ:** APPROVED — เจ้าของโครงการอนุมัติ 2026-10-01 ให้เริ่ม schema/API/UI
**อ้างอิง:** [Project Specs §10.1](2026-09-23-1550-project-specs.md), [ข้อกำหนด DB-first](2026-10-01-db-first-amendment.md), TASK-042

## ขอบเขตที่เจ้าของโครงการยืนยัน

- โมดูลจริงชุดแรกเป็นข้อมูลหลักสินค้าใน Supabase Cloud project ปัจจุบัน โดยใช้ข้อมูลตัวอย่างใน DB เพื่อทดสอบและปรับหน้าจอ ก่อนรับข้อมูลบริษัทจริง
- ข้อมูลขั้นต่ำ: รหัสสินค้า ชื่อ หมวด หน่วยประจำ ราคาขาย และสถานะ
- คำตอบล่าสุดแทนแนวชื่อ-ปี: รหัสสินค้าเป็น **รหัสหมวด-รหัสรูปแบบยา-เลขลำดับ 4 หลัก** เช่น `MED-TAB-0001` โดยไม่ใส่ปี เลขลำดับเริ่มใหม่แยกตามคู่หมวดและรูปแบบยา ระบบเสนอเลขลำดับอัตโนมัติให้ Admin ปรับเป็นเลข 4 หลักอื่นได้ก่อนบันทึกครั้งแรก ต้องไม่ซ้ำ และรหัสที่บันทึกแล้วคงเดิมแม้แก้ชื่อหรือข้อมูลอื่น; ความแรง เช่น `500MG` เป็นข้อมูลสินค้าแยกในอนาคต ไม่ใช้เป็นส่วนท้ายรหัสรอบนี้
- หมวดหมู่ยาและรูปแบบยาเป็นรายการแม่ที่เลือกด้วย ID; ตัวอย่างรหัสหมวด `MED` (ยาแผนปัจจุบัน), `HER` (ยาสมุนไพร/ยาแผนไทย), `SUP` (เวชภัณฑ์) และรหัสรูปแบบ `TAB` (ยาเม็ด), `CAP` (แคปซูล), `SYR` (น้ำเชื่อม), `INJ` (ยาฉีด). ตัวอย่างเหล่านี้เป็นข้อมูลทดสอบ ไม่ใช่รายการครบของบริษัท
- ตัวยา/ชื่อสามัญเป็นรายการแม่แยกที่เลือกด้วย ID ตอนสร้างสินค้า; Admin เพิ่มรายการใหม่จากหน้าเพิ่มสินค้าและเลือกซ้ำในสินค้าถัดไปได้. เลือกคลังที่เกี่ยวข้องหนึ่งแห่งด้วย ID และแก้ได้ภายหลัง โดยการเลือกหรือแก้นี้ไม่สร้าง/ย้ายจำนวน ยอดคงเหลือ Lot หรือ Ledger
- Admin เพิ่ม/แก้/เปลี่ยนสถานะ/ลบเชิงตรรกะและกู้คืนสินค้า; Sales, Manager และ Accounting & CFO อ่านข้อมูลสินค้าโดยไม่เห็นต้นทุนตามคำยืนยันเจ้าของโครงการ
- ยังไม่รับเข้า โอน ตัดสต็อก สร้าง Lot หรือแสดงยอดคงเหลือจำลองว่าเป็นยอดจริง

## ข้อเสนอรายละเอียดสำหรับตรวจรับ

| ข้อมูล | ข้อเสนอ | สถานะ |
|---|---|---|
| รหัสสินค้า | `หมวด-รูปแบบ-เลข 4 หลัก`; ลำดับแยกตามคู่หมวด+รูปแบบ, Admin แก้เลขได้ก่อนบันทึก, code unique และคงเดิมหลังสร้าง | ยืนยัน |
| ชื่อ | ข้อความบังคับ ตัดช่องว่างหัวท้าย | รอตรวจรับ |
| หมวด | เลือก ID จากรายการแม่หมวดที่มีรหัสและชื่อ | ยืนยันการเลือก; รายการจริงรอข้อมูลบริษัท |
| รูปแบบยา | เลือก ID จากรายการแม่รูปแบบยาที่มีรหัสและชื่อ | ยืนยันการเลือก; รายการจริงรอข้อมูลบริษัท |
| ตัวยา/ชื่อสามัญ | เลือก ID จากรายการแม่ตัวยา; Admin เพิ่มชื่อใหม่จากฟอร์มสินค้าได้ | ยืนยัน |
| คลังที่เกี่ยวข้อง | เลือก ID คลังหนึ่งแห่งตอนสร้างและแก้ได้ภายหลัง; ไม่มีผลต่อยอด | ยืนยัน |
| หน่วยประจำ | ข้อความ/ตัวเลือกบังคับ, หนึ่งหน่วยต่อสินค้า, ไม่มีแปลงหน่วย | รอตรวจรับ |
| ราคาขาย | Decimal บาท ≥ 0, สองตำแหน่ง; ไม่คำนวณภาษี/ส่วนลด | รอตรวจรับ |
| สถานะ | ใช้งาน / ไม่ใช้งาน; สถานะนี้ไม่ใช่สถานะคงเหลือหรือหมดอายุ | รอตรวจรับ |
| ID ภายใน | UUID คงเดิม ใช้เชื่อมธุรกรรมในอนาคต แม้แก้ชื่อ | รอตรวจรับ |
| ข้อมูลตัวอย่าง | แยกป้าย `ข้อมูลตัวอย่าง` และ seed ซ้ำโดยไม่ทับข้อมูลที่ผู้ใช้แก้ | รอตรวจรับ |

การลบเชิงตรรกะและกู้คืนใช้สิทธิ์ Admin ตามคำตอบล่าสุด. รายการที่ถูกลบซ่อนจากรายการปกติและกู้คืนได้ โดยรหัสเดิมยังถูกจองไว้ไม่ให้สินค้ารายอื่นใช้. การแก้หน่วยหลังมีธุรกรรม, ต้นทุน และรูปภาพยังไม่ได้รับกฎครบ จึงกันคำสั่งที่เกี่ยวข้องไว้. รูปและต้นทุนไม่อยู่ในชุดขั้นต่ำที่เจ้าของโครงการเลือกสำหรับรอบแรก แต่ยังอยู่ใน Specs หลัก §10.1

รายการแม่หมวด/รูปแบบยา/ตัวยามี UUID ภายในและรหัสหรือชื่อที่แสดง. Admin เพิ่มรายการแม่จากฟอร์มสินค้าได้เพื่อไม่ให้รายการตัวอย่างจำกัดการสร้างสินค้า; เมื่อมีสินค้าอ้างอิงแล้ว ห้ามแก้รหัสหมวดหรือรูปแบบยาจนกว่าจะกำหนดผลกระทบต่อรหัสสินค้า. คลังใช้สามคลังที่ยืนยันใน Specs หลัก §10.1 และไม่เปิดการเพิ่มคลังจากฟอร์มนี้. หน่วยประจำกรอกชื่อหน่วยหนึ่งหน่วยต่อสินค้าในรอบแรก

เลขลำดับอัตโนมัติเลือกเลขว่างถัดไปในคู่หมวด+รูปแบบ; ถ้า Admin เปลี่ยนเลขก่อนบันทึก ต้องตรวจรูปแบบ `0001`–`9999` และ unique code ใน DB. การกดบันทึกพร้อมกันต้องไม่สร้างรหัสซ้ำ; หากเลขที่แสดงถูกใช้ก่อน ให้แจ้งให้เลือก/รับเลขใหม่ ไม่เขียนทับสินค้าเดิม

## หน้าจอรอบแรก

- `/products`: รายการจาก DB พร้อมค้นชื่อ/รหัส, กรองหมวดและสถานะจริง, ไม่แสดงตัวเลข Stock/Lot เดิมที่เป็น Mock
- `/products/create`: ฟอร์มข้อมูลหลักที่เลือกหมวด รูปแบบยา ตัวยา และคลังจาก ID; แสดงรหัสตัวอย่างและช่องเลขลำดับที่ระบบเสนอให้แก้ก่อนบันทึก
- `/products/[รหัสสินค้า]`: ดูข้อมูลหลักและแก้เฉพาะคำสั่งที่อนุมัติ; ใช้ ID ภายในสำหรับความสัมพันธ์ DB
- หลังบันทึกแสดงผลและข้อผิดพลาดภาษาไทย; ไม่กล่าวว่ามีการเคลื่อนไหวคลัง

## รายละเอียดรอบแรกที่เสนอให้ตรวจพร้อมเอกสาร

- ราคาขายเก็บ Decimal สองตำแหน่ง รับค่า 0 ได้สำหรับข้อมูลที่ยังไม่กำหนดราคา แต่ UI แสดงว่าเป็น 0 บาท ไม่ตีความว่าแจกฟรี; ยังไม่คำนวณภาษีหรือส่วนลด
- สถานะ `ใช้งาน/ไม่ใช้งาน` แยกจากการลบเชิงตรรกะ; Admin เปลี่ยนได้, Role อื่นอ่านสินค้าที่ไม่ถูกลบได้
- ข้อมูลตัวอย่างเริ่มจากหมวด MED/HER/SUP, รูปแบบ TAB/CAP/SYR/INJ, ตัวยาตัวอย่าง, สามคลังตาม Specs; แถวที่ seed มีป้ายข้อมูลตัวอย่างชัดเจน และ seed ซ้ำไม่แก้ข้อมูลที่ Admin เปลี่ยนแล้ว
- ค่าเริ่มต้นเลขลำดับเลือกเลขว่างถัดไปในคู่หมวด+รูปแบบ; เมื่อ Admin ใส่เลขสูงกว่ารายการเดิม ระบบใช้เลขว่างถัดไปตามค่ามากสุดของคู่นั้นสำหรับการสร้างครั้งถัดไป

## วิธีตรวจรับ

สร้างสินค้าใน DB แล้วเห็นบนหน้า `/products`; เปิดรายละเอียดด้วยรหัสที่สร้าง; แก้ชื่อ/ราคา/สถานะตามสิทธิ์แล้วข้อมูลคงอยู่หลังรีโหลด; ค้น/กรองตรงกับข้อมูล DB; บันทึกผิดรูปแบบแล้วไม่สร้างข้อมูล; seed ซ้ำแล้วจำนวนตัวอย่างไม่เพิ่ม; Role ที่ไม่มีสิทธิ์เรียก Server Action โดยตรงแล้วถูกปฏิเสธ; ไม่มี Stock Ledger หรือยอดคลังเกิดจากการสร้างสินค้า
