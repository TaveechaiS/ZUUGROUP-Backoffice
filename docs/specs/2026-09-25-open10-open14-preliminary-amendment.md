# ข้อบันทึกเบื้องต้น — OPEN-10 และ OPEN-14

**วันที่ได้รับข้อมูล:** 2026-09-25 (Asia/Bangkok)
**สถานะ:** ข้อสรุปเบื้องต้นจากเจ้าของโครงการ; ยังไม่อนุมัติเป็นกฎพร้อมพัฒนา
**อ้างอิง:** SPEC-PROJECT-001 รุ่น 0.3, OPEN-10, OPEN-14, TASK-026

เอกสารนี้บันทึกคำตอบเบื้องต้นของเจ้าของโครงการ โดยคงส่วนที่ยังไม่ชัดเป็น OPEN ห้ามนำข้อเสนอ/ส่วนที่ไม่ชัวร์ไปทำเป็น validation, schema, policy หรือ behavior จนกว่าจะยืนยัน Specs.

## OPEN-10 — ไฟล์แนบ, Audit และ Archive

- **ชนิดไฟล์ที่ตั้งใจให้รองรับ:** PDF และไฟล์รูปภาพทุกชนิด
- **ขนาดสูงสุด:** 20 MiB ต่อไฟล์ (ผู้ใช้มอบหมายให้ AI เลือก; เลือกให้เหมาะกับ PDF/ภาพหลายหน้า 2–3 แผ่น). ตรวจแล้วว่า Supabase Storage รองรับการตั้งเพดานระดับ Bucket และเพดาน 20 MiB ต่ำกว่าค่าสูงสุด 50 MB ของ Free plan; ยังไม่กำหนดโควต้ารวมต่อรายการ/ลูกค้า. ไฟล์เกิน 6 MB หากใช้ Supabase แนะนำใช้ Resumable Upload เพื่อความน่าเชื่อถือ
- **เอกสารที่ต้องแนบ:** เจ้าของโครงการยังไม่ชัวร์; ตารางด้านล่างเป็นข้อเสนอให้พิจารณา ไม่ใช่รายการบังคับหรือข้อสรุปทางกฎหมายแบบเดียวสำหรับทุกกรณี
- **อายุ Audit Log:** เก็บ 5 ปี (เจ้าของโครงการยืนยัน 2026-09-25); ยังไม่กำหนดจุดเริ่มนับ โดยเจ้าของต้องการรอให้ระบบเสร็จและทดสอบก่อนพิจารณา
- **Archive:** สิทธิ์ดูข้อมูลที่ Archive เป็นของ Admin; วิธี Archive, การกู้คืน, ระยะเวลา/การลบหลัง Archive และ audit ของการเข้าถึงยังไม่กำหนด

### ข้อเสนอรายการเอกสาร (รอเจ้าของอนุมัติ)

| ข้อมูลที่จัดการ | เอกสารที่เสนอ | ขั้นที่เสนอให้แนบ | สถานะ/ข้อควรระวัง |
|---|---|---|---|
| สินค้า/ทะเบียนยา | เลขทะเบียนตำรับยาและหลักฐานการขึ้นทะเบียน/อนุญาตผลิตภัณฑ์; ฉลากและเอกสารกำกับยาฉบับที่ใช้ | ตอนเพิ่มสินค้า; เก็บเลขทะเบียน/วันหมดอายุและไฟล์ตามรุ่น | อย. แยกใบอนุญาตสถานที่ผลิต/นำเข้า/ขาย ออกจากเอกสารผลิตภัณฑ์; ต้องตรวจว่ารายการใดใช้กับยาทุกชนิด |
| ผู้ผลิต/แหล่งผลิต | ใบอนุญาตผลิตในประเทศและหลักฐานมาตรฐาน GMDP/GMP; ผู้ผลิตต่างประเทศใช้ GMP Clearance ตามที่เกี่ยวข้อง | เก็บที่ทะเบียนผู้ผลิต/แหล่งผลิตและเชื่อมกับสินค้า; ตรวจอายุเอกสารเมื่อเพิ่ม/ทบทวนสินค้า | เป็นหลักฐานระดับสถานที่/ผู้ผลิต ไม่จำเป็นต้องแนบซ้ำทุก SKU หากเก็บความสัมพันธ์ได้ |
| ผู้นำเข้า/การนำเข้า | ใบอนุญาตนำหรือสั่งยา, เอกสารผลิตภัณฑ์ตามกรณี; LPI และ Invoice สำหรับการนำเข้าแต่ละครั้ง | ใบอนุญาต/ข้อมูลผลิตภัณฑ์เก็บที่ผู้นำเข้า/สินค้า; LPI/Invoice เก็บต่อเอกสารรับเข้า/Shipment | อย. ระบุว่าการนำเข้าเพื่อจำหน่ายมีขั้นตอนใบอนุญาตและเอกสารผลิตภัณฑ์; LPI ยื่นแยกแต่ละครั้ง |
| Lot/การรับเข้า | Certificate of Analysis (CoA) หรือเอกสารปล่อยผ่านรุ่นผลิต ถ้าผู้ผลิตจัดให้ | ตอนรับเข้าสต็อก ผูกกับ Lot/เอกสารรับสินค้า | ข้อเสนอการควบคุมคุณภาพ; ต้องให้เภสัชกร/QA ยืนยันว่าต้องใช้กับกลุ่มใด |
| ลูกค้าโรงพยาบาล/คลินิก | หลักฐานสถานะนิติบุคคล/หน่วยงานและใบอนุญาตประกอบกิจการสถานพยาบาลที่ยังใช้ได้ (เอกชนใช้ใบอนุญาตประเภท ส.พ.7 หรือใบอนุญาตที่ตรงกับประเภทสถานพยาบาล); ข้อมูลผู้มีอำนาจสั่งซื้อ/รับสินค้า | ตอนเพิ่มลูกค้า; ตรวจเอกสารก่อนเปิดใช้งานลูกค้าหรือทำรายการซื้อขายครั้งแรก | กรม สบส. มีใบอนุญาตประกอบกิจการสถานพยาบาลและใบอนุญาตผู้ดำเนินการ; ยังไม่พบ checklist เดียวที่ยืนยันว่าเอกสารชุดนี้เป็นข้อบังคับสำหรับผู้ซื้อยาทุกประเภท |
| ลูกค้าร้านยา/ผู้ขายยา | ใบอนุญาตขายยาประเภทที่ตรงกับกิจการ เช่น ข.ย.1/2/4 ตามประเภทที่ได้รับอนุญาต | ตอนเพิ่มลูกค้า; ตรวจเลขที่/วันหมดอายุก่อนเปิดใช้งานหรือสั่งซื้อ | ใช้เฉพาะกรณีลูกค้าเป็นผู้ขายยาที่ต้องมีใบอนุญาต; อย. เผยแพร่รายชื่อผู้รับอนุญาตแยกตามประเภท |

ข้อเสนอขั้นตอนระบบ: เพิ่ม/แก้ข้อมูลเอกสารในหน้าสินค้าหรือหน้าลูกค้าตามชนิดข้อมูล; เอกสารตาม Lot/Shipment แนบตอนรับเข้า. กำหนดว่าฟิลด์ใดบังคับและลูกค้าเปิดใช้งานได้เมื่อใดหลังเจ้าของยืนยันประเภทลูกค้าและเภสัชกร/ฝ่ายกำกับดูแลตรวจรายการแล้ว.

**แหล่งทางการที่ตรวจเมื่อ 2026-09-25:** [อย. — ใบอนุญาตสถานที่ผลิต/นำเข้า/ขายยา](https://en.fda.moph.go.th/entrepreneurs-medicines/drug-facility-licensing-01); [อย. — ขั้นตอนนำเข้ายาเพื่อจำหน่ายและ LPI](https://logistics.fda.moph.go.th/imported-for-sale/medicine-import); [อย. — รายชื่อผู้รับอนุญาตขายยาและผู้ผลิตที่ได้รับมาตรฐาน](https://drug.fda.moph.go.th/information-service/category/conditionalreg); [กรมสนับสนุนบริการสุขภาพ — คู่มือใบอนุญาตสถานพยาบาล ส.พ.7/ส.พ.19](https://hss.moph.go.th/fileupload_doc_slider/2020-04-27-25-20-865472.pdf); [อย. — ตัวอย่างใบรับรองผลิตภัณฑ์ยา](https://en.fda.moph.go.th/entrepreneurs-e-cer/category/sample-medicines). สำหรับระบบไฟล์: [Supabase — File limits](https://supabase.com/docs/guides/storage/uploads/file-limits), [Supabase — Resumable uploads](https://supabase.com/docs/guides/storage/uploads/resumable-uploads), [Supabase — Bucket restrictions](https://supabase.com/docs/guides/storage/buckets/creating-buckets). Supabase ระบุ Free plan ตั้ง global limit ได้สูงสุด 50 MB, ตั้งชนิด/ขนาดแยก Bucket ได้ และแนะนำ Resumable Upload เมื่อไฟล์ใหญ่กว่า 6 MB; จึงรองรับแนวทาง 20 MiB แต่การเลือกวิธีอัปโหลดจริงเป็นเรื่องตอนออกแบบ implementation.

## OPEN-14 — บัญชีผู้ใช้, Role และ Admin คนสุดท้าย

- **ผู้สร้างบัญชี:** Admin เป็นผู้สร้างบัญชีผู้ใช้
- **ตั้งรหัสผ่านครั้งแรก:** Admin เป็นผู้ตั้งให้
- **Role:** ผู้ใช้หนึ่งคนมี 1 Role; Role หมายถึงตำแหน่งงานและระบบกำหนดสิทธิ์ตาม Role. บันทึกเป็นแนวทางว่า Admin เลือก Role ตอนสร้างบัญชี; ไม่มีระบบสมัคร Role เอง
- **กู้คืนผู้ใช้:** Admin เป็นผู้กู้คืนบัญชีที่ถูกระงับหรือลบ
- **Admin และบัญชีสุดท้าย:** Admin ไม่ควรถูกระงับ; เจ้าของโครงการระบุว่า Admin ไม่สามารถสมัคร/ลบผ่านระบบ และอาจทำเพิ่ม/ลบตรงใน DB. บันทึกเป็นความตั้งใจเบื้องต้นว่าการสร้าง/ลบ Admin ไม่ทำผ่าน UI; วิธี DB-only และความหมาย “บัญชีเวียน” ยังต้องยืนยัน. จำนวน Admin ไม่ตายตัวและอาจน้อยกว่า 5; ยังไม่สรุปวิธีป้องกันการลบ Admin คนสุดท้ายหรือกู้คืนเมื่อเข้าใช้ไม่ได้

## สิ่งที่ยังต้องยืนยันก่อน Gate ผ่าน

1. ชุดรูปแบบไฟล์ภาพที่รับได้อย่างปลอดภัย และโควต้ารวมต่อรายการ/ลูกค้า (เพดานต่อไฟล์ 20 MiB ถูกกำหนด)
2. ประเภทเอกสารที่ต้องบังคับตามประเภทยา/ผู้ผลิต/ลูกค้า และขั้นตอนที่ต้องมีเอกสาร; ทบทวนข้อเสนอตารางข้างต้นกับเภสัชกร/ฝ่ายกำกับดูแล
3. จุดเริ่มนับ Audit 5 ปี โดยพิจารณาหลังระบบเสร็จและผ่านทดสอบ
4. วิธี/รอบการ Archive, การกู้คืน และสิทธิ์อื่นนอกเหนือการดูของ Admin
5. ขอบเขต DB-only สำหรับสร้าง/ลบบัญชี Admin, ความหมายของบัญชีเวียน, การป้องกัน Admin คนสุดท้ายจากการลบ/ระงับ และวิธีกู้คืนการเข้าถึง

เจ้าของโครงการตรวจทานบันทึกเบื้องต้นและยืนยันว่าข้ออื่นถูกต้องเมื่อ 2026-09-25; รายการที่ระบุว่ายังไม่ชัวยังเป็นประเด็นรอคำตอบ ไม่ใช่การอนุมัติกฎสุดท้าย.

**ผลต่อการเริ่มงาน:** G-04 และ G-10 ยังคงไม่ผ่านจากข้อมูลเบื้องต้นนี้. อนุญาตให้จัดทำ Specs/คำถามต่อได้; ห้ามเริ่มงานโค้ด Auth/RBAC ที่พึ่ง OPEN-14 หรือ Storage/Audit retention/archive ที่พึ่ง OPEN-10.
