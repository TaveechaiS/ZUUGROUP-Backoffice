# ข้อกำหนดเพิ่มเติม — เปลี่ยน Mock เป็นข้อมูลตัวอย่างใน DB และการทำงานจริง

**วันที่:** 2026-10-01 (Asia/Bangkok)
**อ้างอิง:** Project Specs §1.2, DEC-003, §22.1–22.4 และคำยืนยันเจ้าของโครงการ 2026-10-01
**สถานะ:** ยืนยันทิศทางและสภาพแวดล้อม; รายละเอียดรายโมดูลยังต้องตรวจรับก่อนเขียนพฤติกรรมจริง

## สิ่งที่เจ้าของโครงการยืนยัน

- ใช้ Supabase Cloud project `zuugroup-web` ปัจจุบันเป็นสภาพแวดล้อมทดสอบสำหรับข้อมูลตัวอย่างที่บันทึกจริงใน PostgreSQL
- เดินงานให้หน้าเว็บอ่าน/เขียนข้อมูลผ่าน DB และใช้งานได้จริงตามกฎที่ยืนยันแล้ว เพื่อให้ตรวจ UI และพฤติกรรมในรอบเดียว; ข้อมูลบริษัทจริงจะเติมภายหลัง
- กฎที่ยังอยู่ใน OPEN ให้ทำเฉพาะส่วนที่กำหนดชัดก่อน และตัดสินส่วนที่เหลือทีละโมดูล
- งาน DB ชุดแรกเป็น **ข้อมูลหลักสินค้า**: รหัส ชื่อ หมวด หน่วย ราคาขาย และสถานะ; ยังไม่ทำการรับเข้า โอน ตัดสต็อก หรือแสดงยอดคงเหลือว่าเป็นข้อมูลจริง
- คำตอบล่าสุดแทนรูปแบบชื่อ-ปีเดิม: รหัสสินค้าประกอบจาก **หมวดหมู่ยา-รูปแบบยา-เลขลำดับ 4 หลัก** เช่น `MED-TAB-0001`; เลขลำดับรันแยกตามคู่หมวด+รูปแบบ ระบบเสนอให้และ Admin แก้ก่อนบันทึกได้; รหัสสินค้าที่บันทึกแล้วต้องคงเดิมเพื่อไม่ให้เอกสารอ้างอิงเปลี่ยน
- ตอนสร้างสินค้าให้เลือกข้อมูลแม่ด้วย ID ได้แก่หมวดหมู่ รูปแบบยา และคลัง/ยา ตามความหมายที่กำลังยืนยัน; การเลือกคลังยังไม่สร้างจำนวนหรือยอดคงเหลือ

## ขอบเขตของคำว่า “ใช้งานได้จริง”

แต่ละโมดูลที่เปิดงานจริงต้องมี schema/migration, การอ่านเขียนผ่าน Server, validation, สิทธิ์ที่ได้รับอนุมัติ, ประวัติการเปลี่ยน, การลบ/กู้คืนหรือยกเลิกตามชนิดข้อมูล, ข้อมูลทดสอบที่สร้างซ้ำได้, และการตรวจรับโดยเจ้าของโครงการ. หน้า Mock ที่ยังไม่ถึงเกณฑ์นี้ต้องติดป้ายข้อมูลจำลองไว้และไม่กล่าวว่าเป็นงานจริง

## เส้นแบ่งระหว่างส่วนที่ทำได้กับส่วนที่รอ

- การยืนยันนี้ไม่ปิด OPEN-01–07, OPEN-10–13, OPEN-15–16 หรือ Gate ที่เกี่ยวข้อง; ห้ามใช้ข้อมูลตัวอย่างเป็นกฎธุรกิจจริง
- ห้ามเขียนคำสั่งที่เพิ่ม/ตัด/โอนยอดสต็อก, คำนวณเงิน/ภาษี/กำไร/อายุหนี้, อนุมัติ, ออกเลขเอกสาร/PDF จริง หรือเปิดสิทธิ์รายข้อมูลที่ยังไม่กำหนด
- ห้ามนำข้อมูลจริงเก่ามา import ก่อน OPEN-13; ห้ามเปิด Production หรือใช้ DB ทดสอบนี้แทนการตรวจรับข้อมูลจริง
- การเปลี่ยนจาก Mock รายหน้าเป็นข้อมูล DB ต้องทำทีละโมดูล; หน้าอื่นยังอยู่ในสถานะ Mock จนกว่าจะผ่านเกณฑ์จริง
- ใช้ migration เพิ่มแบบตรวจสอบได้และ seed ข้อมูลตัวอย่างที่รันซ้ำโดยไม่ลบข้อมูลของผู้ใช้; แยก/ติดป้ายข้อมูลตัวอย่างให้ชัด

## ข้อมูลที่ต้องอนุมัติก่อนแต่ละงาน

Specs รายโมดูลต้องระบุฟิลด์บังคับ, รหัสอ้างอิง, สถานะ, คำสั่ง, Role และขอบเขตข้อมูล, กรณีลบ/กู้คืน, ตำแหน่งเมนู และข้อมูลตัวอย่างที่จะใช้ตรวจ. ถ้าข้อใดพึ่ง OPEN ให้กันคำสั่งนั้นไว้จนกว่าจะได้คำตอบ ไม่สร้างค่าเริ่มต้นสมมุติเพื่อให้ดูเหมือนทำงานครบ
