# คู่มือกู้คืนบัญชี Admin

**ผู้รับผิดชอบ:** เจ้าของโครงการ
**ขอบเขต:** กู้คืนเมื่อ Admin ใช้งานไม่ได้หรือไม่มีบัญชี Admin ที่เข้าเว็บได้

## สถานะปัจจุบัน

มีเครื่องมือ `scripts/recover-admin.mjs` สำหรับเจ้าของโครงการแล้ว แต่ยังไม่ผ่านการทดสอบกับ Supabase Cloud/ฐานข้อมูลจริง ต้องทดสอบก่อนเปิด Auth ใช้งานจริง

## กติกาความปลอดภัย

- ใช้เฉพาะ Project Owner ที่มีสิทธิ์เข้าถึง Supabase project และผู้ปฏิบัติงานที่เจ้าของโครงการมอบหมาย
- การเปลี่ยนรหัสผู้ใช้ใช้ Supabase Auth Admin API จากสภาพแวดล้อมฝั่งเซิร์ฟเวอร์/เครื่องผู้ดูแลที่ควบคุมได้เท่านั้น; ห้ามส่ง Secret key ไป Browser, Git, แชต หรือ command line ที่บันทึกลงประวัติ
- ห้ามแก้ตารางระบบ `auth.users` ด้วย SQL เพื่อเปลี่ยนรหัสผ่าน
- Role เป็นข้อมูลสิทธิ์ของแอป ต้องกู้คืนผ่านชั้นจัดการ Role ที่ได้รับอนุญาตในระบบ ห้ามใช้ `user_metadata` เป็นแหล่งตัดสินสิทธิ์
- ไม่ส่งลิงก์หรือรหัสผ่านทางอีเมล; ผู้รับต้องยืนยันตัวตนผ่านช่องทางส่วนตัวที่เจ้าของโครงการตรวจสอบได้
- ไม่บันทึกรหัสผ่านหรือ Secret key ลงในบันทึกเหตุการณ์

## กรณีมี Admin ที่เข้าเว็บได้อย่างน้อยหนึ่งคน

1. Admin ที่ยังเข้าได้ตรวจสอบตัวตนผู้ขอและบัญชีเป้าหมาย
2. ตั้งรหัสใหม่ให้บัญชีเป้าหมายจากหน้าจัดการผู้ใช้
3. หากบัญชีนั้นถูกปิดใช้งาน ให้เปิดใช้คืนตามสิทธิ์และตรวจว่าระบบยังมี Admin ที่ใช้งานได้อย่างน้อยหนึ่งบัญชี
4. แจ้งรหัสใหม่กับเจ้าของบัญชีผ่านช่องทางส่วนตัวที่ยืนยันตัวตนได้ และให้ลงชื่อเข้าเว็บเพื่อตรวจผล
5. บันทึกผู้อนุมัติ ผู้ดำเนินการ บัญชีเป้าหมาย วันเวลา และผล โดยไม่บันทึกรหัสผ่าน

## กรณีไม่มี Admin เข้าเว็บได้

1. เจ้าของโครงการเข้าสู่ Supabase Dashboard ด้วยบัญชีส่วนตัวที่มีสิทธิ์เจ้าของ Project; ห้ามใช้บัญชีร่วม
2. เปิด Authentication → Users เพื่อค้นหาและยืนยัน Auth User ID ของบัญชีที่ต้องกู้คืน
3. ตรวจว่า `.env.local` บนเครื่องผู้ดูแลมี `NEXT_PUBLIC_SUPABASE_URL`, `DATABASE_URL` และ `SUPABASE_SECRET_KEY` หรือ `SUPABASE_SERVICE_ROLE_KEY` โดยไม่พิมพ์ค่าออกมา
4. เปิด PowerShell ในโฟลเดอร์โครงการแล้วเรียก `npm.cmd run recover:admin -- --i-am-project-owner` (หรือใช้ `npm run recover:admin -- --i-am-project-owner` ใน Command Prompt) ป้อนอีเมล รหัสพนักงาน ชื่อ และ Auth User ID จาก Dashboard; เว้น Auth User ID ว่างเฉพาะเมื่อจะสร้าง Auth user ใหม่
5. พิมพ์ `RECOVER ADMIN` เพื่อยืนยัน แล้วใส่รหัสใหม่เมื่อเครื่องมือถาม รหัสจะไม่แสดงบนจอและไม่อยู่ใน command history เครื่องมือจะตั้งรหัสผ่านผ่าน Auth Admin API, คืนสถานะ Active และ Role Admin, ล้างเครื่องหมายลบเชิงตรรกะหากมี และบันทึก Audit โดยไม่เก็บรหัสผ่าน
6. ตรวจว่าบัญชีกลับมาเข้าเว็บได้และเห็นเมนู/สิทธิ์ Admin; ตรวจว่าระบบมี Admin ที่ใช้งานได้อย่างน้อยหนึ่งบัญชี
7. ส่งรหัสใหม่ให้เจ้าของบัญชีผ่านช่องทางส่วนตัวที่ยืนยันตัวตนได้ จากนั้นบันทึกรายละเอียดเหตุการณ์โดยไม่เก็บรหัสผ่านหรือ Secret

สำหรับการสร้าง Admin คนแรก ให้ทำขั้นตอนเดียวกันโดยเว้น Auth User ID ว่าง เครื่องมือจะสร้าง Auth user และแถวบัญชีภายในใหม่ หลังจากตั้งค่า Supabase Auth ตาม [Security](../SECURITY.md) แล้ว

> หากเครื่องมือแจ้งว่า Auth user มีอยู่แล้วแต่ไม่พบในฐานข้อมูล ให้ค้นหา Auth User ID ใน Dashboard และเรียกเครื่องมือใหม่โดยระบุ ID นั้น ห้ามใช้ ID ที่อีเมลไม่ตรงกับบัญชีเป้าหมาย

## รายการที่ต้องทดสอบก่อนเปิด Auth จริง

- การสร้างบัญชีด้วย Auth Admin API ไม่ส่งอีเมลหรือลิงก์ และบัญชีเข้าใช้ด้วยรหัสที่ Admin ตั้งได้
- การตั้งรหัสใหม่จาก Admin UI ใช้งานได้โดยไม่มีอีเมล
- ระบบปฏิเสธการปิดใช้งาน ลบ หรือลด Role ของ Admin คนสุดท้าย
- Recovery utility ใช้ได้เมื่อไม่มี Admin เข้าเว็บ และคืนทั้งการเข้าสู่ระบบกับ Role ที่ถูกต้อง
- Secret key ไม่ปรากฏใน Browser bundle, log, Git หรือหน้าจอผู้ใช้
- มี Audit record สำหรับการสร้าง/แก้ไขบัญชีและการกู้คืน โดยไม่เก็บรหัสผ่าน

## เอกสาร Supabase ที่ใช้อ้างอิง

- [Auth Admin API: updateUserById](https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid) — เปลี่ยนรหัสผ่านด้วย Auth Admin API; ใช้ฝั่งเซิร์ฟเวอร์และห้ามเผย Secret key ใน Browser.
- [Auth Users](https://supabase.com/docs/guides/auth/users) — ตำแหน่ง Authentication → Users และการแยกการจัดการผู้ใช้จาก Management API.
- [Auth Admin API: createUser](https://supabase.com/docs/reference/javascript/auth-admin-createuser) — สร้างผู้ใช้จาก trusted server; API รองรับ password และ email confirmation แบบผู้ดูแล.
